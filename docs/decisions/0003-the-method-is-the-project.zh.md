# 0003 — 项目是方法；Cairn 是它的第一个产物

- 状态：已接受
- 日期：2026-10-31

## 背景

最初的目标是判断 **superpowers** 和 **Impeccable** 能否融合成一种工作方式，提高构建产品
（文档、代码、工作流）的效率，然后探索一种长周期工作无人值守仍能落地的模式。同一个项目就是
试金石：把正在构建的东西当作自己的最佳实践。

早期文档把 Cairn 描述为“面向长周期编码工作的 mission 运行时”。这把范围收窄到代码，并把产物
放到中心。它还让一个会话可以读完协议、看到绿色闸门，却仍然丢失目标。

## 决定

项目是方法。Cairn 是它的第一个产物。

- 目标是可重复、可审计、可自我迭代的构建产品的方式。
- superpowers 提供流程；Impeccable 提供标准；Cairn 提供连续性、证据和漂移控制。
- Cairn 可以被替换。方法必须在替换后存活。
- 第一个用户是作者：先在这个仓库上证明，再推广。

## 后果

- `README.md` 以方法和目标开头，而不是运行时。
- 每个任务声明 `serves: [A#]`；审查问“这服务于目标吗？”，而不只是“闸门绿了吗？”。
- `docs/drift-control.md` 是合同的一部分：每个保障措施都指名它的执行点。
- 范围是文档、代码和工作流——不只是编码。
