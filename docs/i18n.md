# Language policy / 文档语言政策

Decision (2026-10-31): the documentation is bilingual. English is the contract language;
Chinese is the author's reading language. A Chinese file never overrides the English canonical
file.

2026-10-31 决定：文档双语。英文是契约语言，中文是作者的阅读语言。中文文件永远不覆盖英文权威文件。

## Canonical and translation / 权威与译本

- **Canonical / 权威**：`README.md`, `docs/protocol.md`, `docs/drift-control.md`,
  `docs/automation.md`, `docs/decisions/*.md`, and the three mission contracts
  (`mission.md`, `policy.md`, `plan.md`). Machine-checked fields — frontmatter keys, event
  names, CLI flags, gate ids — stay English only. The validator parses the canonical file.
- **Translation / 译本**：`README.zh-CN.md` and `docs/*.zh.md`. Each starts with a comment
  naming the source path and the commit it translates. Translations are not hash-frozen and
  are not parsed by the validator.
- **Staleness / 过期**：when the canonical file changes, the translation is stale until
  updated. The header makes the source commit visible. Do not edit a translation to disagree
  with the canonical file; fix the canonical file or update the translation.
- **Evidence / 证据**：a translation is never evidence in a gate or a ledger event. The
  canonical file is.

## Why English is canonical / 为什么英文是权威

The protocol is consumed by code, hashes, and the validator. Translating the file that the
validator parses would create two contracts that can disagree. The Chinese companions carry the
explanation; the English file carries the contract. This is a deliberate split, not a
preference for English.

协议要被代码、哈希和校验器消费。把校验器解析的文件再翻译一份，会制造两个可能互相矛盾的契约。
中文译本负责解释，英文文件负责契约。这是有意的分工，不是偏好英文。

## Rule for new documentation / 新文档规则

A new human-facing document ships with a Chinese companion in the same change, or is listed as
pending in this table. A document that exists only in one language is a known gap, not an
invisible one.

新的面向人的文档要么在同一次变更里带上中文译本，要么在这张表里登记为待办。只存在一种语言的
文档是已知缺口，不是隐形缺口。
